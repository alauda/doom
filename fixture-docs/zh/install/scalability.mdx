# 容量规划 \{#scale}

在安装管理集群之前，必须根据业务目标和实际需求选择合适的安装场景。不同场景对基础设施资源分配和架构设计有不同要求。以下是三种典型场景的规划建议：

## 安装场景选择 \{#scenario}

### 场景一：功能验证

**适用范围**
该场景适用于平台功能验证、演示环境搭建或技术可行性测试。其仅用于验证平台的核心功能，不承载生产级业务流量，资源配置为最低级别。

**核心特性**

- **单节点部署**：控制平面和计算功能集成在单个节点上。
- **轻量负载**：仅运行核心平台组件，且不超过 10 个演示 pods。
- **非生产使用**：不满足业务连续性和高可用要求。

**资源配置要求**

| 维度   | 规格要求            |
| ------ | ------------------- |
| 节点数 | 1（物理机或虚拟机） |
| CPU    | ≥16 核              |
| 内存   | ≥32GB               |

**架构说明**

- 管理集群以单节点形式部署，集成所有控制和计算功能。
- 所有业务负载均运行在该节点上（建议演示 pods 数量 ≤ 10）。
- 不支持水平扩展，因此不适用于生产环境。

---

### 场景二：ISV 集成交付

**适用范围**
该场景面向 ISV（Independent Software Vendors，独立软件供应商）的标准化交付需求。安装管理集群时，既承担平台管理，也直接运行 ISV 应用，无需额外部署业务集群。

**核心特性**

- **生产级部署**：直接承载 ISV 业务应用，满足生产环境的 SLA 要求。
- **资源协同**：节点配置同时满足平台组件需求和 ISV 应用负载。
- **高可用保障**：至少 3 个控制节点构成高可用架构。

**资源配置要求**

| 部署模式     | 节点类型 | 数量 | 最低规格              | 推荐规格           | 说明                                |
| ------------ | -------- | ---- | --------------------- | ------------------ | ----------------------------------- |
| **最小部署** | 控制节点 | 3    | 8C16GB + ISV 需求     | 12C24GB + ISV 需求 | 建议预留约 30% 冗余资源             |
| -            | 计算节点 | 0    | —                     | —                  | 控制节点共同承担 ISV 应用运行       |
| **推荐部署** | 控制节点 | 3    | 8C16GB                | 12C24GB            | 运行 Kubernetes 组件和平台控制平面  |
| -            | 计算节点 | ≥2   | 基于 ISV 应用负载需求 | —                  | 独立运行 ISV 应用；建议采用 HA 部署 |

**架构说明**

- 安装管理集群时同步部署平台组件和 ISV 业务 pods，建议使用 node taints 隔离关键组件。
- 建议 ISV 应用运行在专用计算节点上，以避免与控制平面资源竞争。
- 扩容建议：每新增 50 个业务 pods，建议根据 ISV 应用资源需求增加 1 个计算节点。

---

### 场景三：多集群管理（数据中心级）

**适用范围**
该场景适用于大型企业数据中心环境，需要对跨云、跨地域的多个业务集群进行统一管理。随着业务集群数量增加，管理集群必须动态扩展计算节点和资源配置，以确保高可用和高性能。

**核心特性**

- **混合管理**：支持跨云、跨地域业务集群统一管理。
- **弹性扩容**：管理集群资源随接入业务集群数量线性扩展。
- **物理隔离**：建议控制平面与计算平面采用物理隔离部署，以保障系统稳定性。

**基础资源配置**

| 节点类型 | 数量   | 最低规格 | 推荐规格 | 部署策略                 |
| -------- | ------ | -------- | -------- | ------------------------ |
| 控制节点 | 3 或 5 | 8C16GB   | 16C32GB  | 独立部署，启用反亲和策略 |
| 计算节点 | ≥2     | 12C24GB  | 24C48GB  | 建议预留 30% 资源冗余    |

**动态扩容规则**

1. **纵向扩展**：单个节点可逐步升级（例如：12C24GB → 24C48GB → 48C96GB）。
2. **横向扩展**：每接入 10 个业务集群，建议将计算资源提升 20%（增加节点数量或规格）。
3. **监控触发**：当 CPU/内存使用率持续超过 70% 时，启动扩容措施。

**架构说明**

- 控制平面由 3 个节点组成 ETCD 集群，建议启用 TLS 加密并定期进行快照。
- 建议将关键平台组件部署在独立计算节点上，以避免资源争用。
- 灾备建议：跨多个可用区部署，确保计算节点分布在至少 2 个物理故障域中。

---

### 全局规划建议

1. **资源冗余**：建议在生产环境中预留至少 30% 的资源，以应对突发负载峰值。
2. **网络规划**：管理集群应部署在专用 VPC 或 VLAN 中，确保带宽 ≥1Gbps。
3. **存储隔离**：建议 ETCD 存储使用 NVMe SSD，并与业务存储保持物理隔离。
